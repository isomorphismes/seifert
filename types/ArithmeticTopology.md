## What is implemented now?

Pure Idriç-style definitions over the existing 3-block scene:

- Signed **unwrapped block rotations**, in turns.
- Signed **relative endpoint rotations** of the vertical/horizontal bands.
- A fail-closed numeric readout type: either Available(label, value, unit)
  or Unavailable(label, prerequisites). The UI should never print an invented 0.
- Integer arithmetic for genus from **certified surface counts**, and linking
  from mixed crossing signs of a **validated, oriented closed-link diagram**.
- A residual for verifying Lk = Tw + Wr **when** independently validated
  closed-ribbon values are supplied.

The repaired modules typecheck with current Idriç source
`ff4d852862a3942592f8ade9afde8d409d9803be`. The executable host checks pass
17 groups, including the six endpoint fixtures below. See
[the retained attempt and exact compiler evidence](../examples/autogenerated/topology-readouts/attempt.md)
and [the Grease runner](../_/check-readouts.grease).

`PrototypeScalar` explicitly retains the original sketch's binary64 host
representation; it no longer shadows Idriç's whole-number `Number`. This is
host numerical evidence, not a current Float16/Float32 backend or native ABI
qualification. The Android app does not consume this module at runtime.
The integer genus and crossing functions operate exactly on Integer values.
NaN, infinity and overflowing endpoint subtraction return Unavailable rather
than an Available numeric diagnostic.

## Exact live-readout convention

The C scene owns unwrapped signed angles (radians) on the common cube
rotation axis (1,1,1)/sqrt(3). With corner = C, upper = U, right = R:

    tau = 2*pi
    vertical_relative_endpoint_turns   = (U - C) / tau
    horizontal_relative_endpoint_turns = (R - C) / tau

These values are *commanded relative rotations*. They are NOT the twist
integral of a geometrically framed band about its tangent. In particular,
one full cube rotation makes the first value equal +1 if only the upper
cube turns; it makes **both** values equal -1 if only the corner turns.

| U | C | R | Vertical relative turns | Horizontal relative turns |
| --- | --- | --- | --- | --- |
| 0 | 0 | 0 | 0 | 0 |
| tau | 0 | 0 | +1 | 0 |
| 0 | tau | 0 | -1 | -1 |
| 0 | 0 | tau | 0 | +1 |
| tau/4 | -tau/4 | 3*tau/4 | +0.5 | +1 |
| 2*tau | tau | -tau | +1 | -2 |

These fixtures now execute against the checked module. Ordinary function names
in source use snake_case; the older camelCase descriptions below identify the
same mathematical operations for continuity.

Additional expected arithmetic fixtures:

- genusFromCertifiedCounts(1, 1) = Just 0 (disk).
- genusFromCertifiedCounts(0, 2) = Just 0 (annulus).
- genusFromCertifiedCounts(-1, 1) = Just 1 (once-punctured torus).
- genusFromCertifiedCounts(0, 1) = Nothing (nonintegral genus).
- linkingFromGivenMixedCrossings([PositiveCrossing, PositiveCrossing]) = Just 1.
- linkingFromGivenMixedCrossings([PositiveCrossing, NegativeCrossing]) = Just 0.
- linkingFromGivenMixedCrossings([PositiveCrossing]) = Nothing.

The crossing examples assume the inputs really are the mixed crossings of a
validated oriented closed two-component link diagram, which this module
cannot itself verify.

## Domain gates / mathematical conditions

### Actual geometric twist (Dennis–Hannay)

For a differentiable regular centerline c(s) with unit tangent t(s) and
smooth transverse unit ribbon direction u(s) perpendicular to t(s):

    Tw = (1/(2*pi)) * integral [(t cross u) dot du/ds] ds

The app's Hermite centerline and width direction do not currently supply a
validated globally perpendicular framing. A future implementation must
project/re-normalize and handle degeneracies before reporting Tw.

### Writhe and linking (Rolfsen, Dennis–Hannay)

Writhe is a geometric Gauss self-integral, not a topological invariant.
A linking number requires **two disjoint closed oriented curves**. For
a valid closed framed ribbon, Lk = Tw + Wr; all three values must be
computed from that ribbon and checked for numeric consistency.

For a valid oriented planar link diagram with two closed components:

    Lk = (sum of signs of all mixed crossings) / 2

The pure sign-summing function cannot establish that a diagram is valid.

### Seifert genus and Alexander polynomial (Seifert, Alexander)

For a connected, compact, orientable surface with b boundary components:

    chi = 2 - 2*g - b

The module checks arithmetic consistency but NOT orientability or mesh
topology. The genus of a selected spanning surface is not necessarily the
**knot genus** (the minimum genus over all spanning surfaces). Once an oriented Seifert surface, cycle basis and push-offs are
available, a Seifert matrix V gives an Alexander polynomial represented
by det(V - t * transpose(V)), up to multiplication by ± t^k.

### Arithmetic topology (Morishita)

Legendre symbols are **not** generated by a geometric drag. They depend on
odd prime/arithmetic inputs. Likewise the knot/primes correspondence,
Milnor invariants vs. residue symbols, and Alexander vs. Iwasawa modules
are separate number-theoretic constructions awaiting their own typed domains.
